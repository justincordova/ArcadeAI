# 01 — Monorepo Scaffold

## Overview

Stand up the empty ArcadeAI monorepo: Bun workspaces, a Vite+React web app, a Fastify+Pino server, a shared Drizzle+SQLite db package, and root-level tooling (Biome, TS base config, license, env example). The end state is a `bun run dev` that boots web on `:5173` and server on `:3000`, with the web app successfully fetching the unauthenticated `GET /api/health` endpoint cross-origin. No auth, no domain logic, no LLM code in this step.

## Goals

- Bun workspaces resolving `@arcadeai/db` and `@arcadeai/shared` from local paths.
- `apps/web`: Vite + React + TypeScript + Tailwind v4 + TanStack Router (file-based) + TanStack Query, dev server on `:5173`.
- `apps/server`: Fastify + Pino (`pino-pretty` in dev), dev server on `:3000`, with `@fastify/cors` configured against `WEB_ORIGIN`.
- `packages/db`: Drizzle schema scaffolding + SQLite client + migration runner + post-migrate raw-SQL step that creates the `rag_embeddings` `vec0` virtual table (SPEC §5). Schema files for the tables in SPEC §5 may be stubbed but no domain logic.
- `packages/shared`: empty package with `plans.ts`, `models.ts`, `types.ts` placeholders so workspace resolution works from day one.
- Root: `biome.json` (lint + format), `tsconfig.base.json`, `package.json` with `dev`, `build`, `lint`, `format`, `check` scripts, `LICENSE` (MIT), `README.md`, `.env.example` (matching SPEC §15), `.gitignore` (matching SPEC §4).
- Unauthenticated `GET /api/health` returns `{ ok: true, version: '<package version>' }` (SPEC §11, §14) and is fetchable from the web app cross-origin with `credentials: 'include'`.

## Non-goals

- No Better Auth, no `/sign-in`, no protected routes, no session middleware (step 2).
- No `games`, `messages`, `usage_log` domain logic — schema files may exist as table definitions only, with no service layer (step 3+).
- No LLM SDK wiring, no SSE, no RAG, no `vec0` data — only the empty virtual table is created (step 4+, step 9).
- No rate limiting plugin (step 13). CORS is the only cross-cutting plugin in this step.
- No shadcn/ui primitives installed (added as needed in later steps per SPEC §12).
- No tests (SPEC §2 — added incrementally).
- No production build pipeline beyond `tsc --noEmit` parity check (SPEC §4).
- No pre-commit hook setup (Lefthook/Husky is "optional" per SPEC §4).

### Workspace resolution

Root `package.json` declares:
```json
"workspaces": ["apps/*", "packages/*"]
```
`apps/web` and `apps/server` depend on `@arcadeai/db` and `@arcadeai/shared` via `"workspace:*"`. Bun resolves these symlinks natively. Vite picks up the TS path aliases from `tsconfig.base.json` via `vite-tsconfig-paths`. `tsc --noEmit` resolves the same aliases via `paths` declared in the base config.

### Package boundaries

- `packages/shared` has zero runtime dependencies in this step; it exists so step 2+ can import without restructuring.
- `packages/db` owns SQLite, Drizzle, and the `vec0` post-migrate step. The actual `sqlite-vec` extension is **not** loaded in this step (SPEC §19 step 9 owns extension loading); only the virtual table is created. The `CREATE VIRTUAL TABLE` statement requires the extension to be loaded, which means either (a) we defer the post-migrate step until step 9, or (b) we load the extension already in step 1. SPEC §19 step 1 explicitly says "including post-migrate `vec0` table creation" — see "Open questions" below.
- `apps/server` only depends on `@arcadeai/db` and `@arcadeai/shared` (the latter is unused in this step but wired for parity).
- `apps/web` only depends on `@arcadeai/shared` (also unused but wired).

### Dev orchestration

Root `dev` script: `bun run --filter '*' dev` (SPEC §4). Each workspace defines its own `dev`. If `--filter` is flaky in practice the spec sanctions a `concurrently` fallback — we'll start with the native form and only swap if observed broken.

### Health endpoint

`GET /api/health` is registered directly on the Fastify instance (no auth plugin yet). Response shape per SPEC §11: `{ ok: true, version: '<package version>' }`, where `version` is read from `apps/server/package.json`.

### CORS

Per SPEC §14:
- `@fastify/cors` registered with `origin: process.env.WEB_ORIGIN ?? 'http://localhost:5173'`, `credentials: true`.
- Web `fetch` to `http://localhost:3000/api/health` uses `credentials: 'include'` for parity with later auth flows.

## Key decisions

### Bun workspaces (vs. pnpm/npm/yarn)

Mandated by SPEC §3, §4. Bun is the chosen runtime and its workspace resolution is native, fast, and removes the need for a separate package manager. No decision to make here — recording for completeness.

### Drizzle + raw SQL for `vec0` (vs. all-SQL or all-Drizzle)

SPEC §5 is explicit: the `vec0` virtual table cannot be expressed in Drizzle's schema DSL, so a post-migration raw SQL step runs after `drizzle-kit migrate`. We implement this as `packages/db/src/post-migrate.ts` invoked from `migrate.ts`. Rationale: keeps the regular schema in Drizzle (typed, migrated, diffable) while isolating the one capability gap to a single line of SQL. Idempotent via `IF NOT EXISTS`.

### Single Biome config at repo root (vs. per-workspace configs)

SPEC §4 mandates a single `biome.json` at repo root. Rationale: one source of truth for lint + format rules across all workspaces, no drift, one command (`bun run check`) covers the whole repo. Biome handles both linting and formatting in one tool, replacing ESLint + Prettier.

### Tailwind v4 (vs. v3)

SPEC §3 pins Tailwind v4. v4 ships a Vite plugin (`@tailwindcss/vite`) that replaces the PostCSS pipeline for v3. We'll use the Vite plugin form to minimize config surface.

### TanStack Router file-based routes (vs. code-based)

SPEC §3, §4 (`routeTree.gen.ts` is gitignored — implies the Vite plugin generates it). Rationale: type-safe routes, less boilerplate, matches the SPEC's stated convention.

### `tsc --noEmit` build script for server (vs. no build script)

SPEC §4: "Bun runs TypeScript directly, but a `build` script that does typecheck (`tsc --noEmit`) is included for CI parity." We honor this so future CI can run `bun run build` uniformly.

### Health endpoint version sourced from `apps/server/package.json`

SPEC §11 says `version: '<package version>'`. The server's own `package.json` is the natural source. Read once at boot via a static import (`assert { type: 'json' }`) to avoid filesystem reads per request.

## Open questions

1. **`vec0` virtual table at step 1 vs. step 9.** SPEC §19 step 1 says "including post-migrate `vec0` table creation," but `CREATE VIRTUAL TABLE ... USING vec0` requires the `sqlite-vec` extension to be loaded on the connection that runs it, and SPEC §19 step 9 says "install sqlite-vec extension and load via `db.loadExtension()`." Two readings:
   - **(a) Load the extension already in step 1** so the post-migrate step can succeed. The extension is a runtime dependency that we install as a package now and load in `client.ts`.
   - **(b) Defer the post-migrate `vec0` step** to step 9 — implement the post-migrate hook structure now but no-op the actual `CREATE VIRTUAL TABLE` until the extension is wired.
   
   Reading (a) is the literal interpretation of step 1's deliverables; reading (b) keeps step 1 free of the `sqlite-vec` extension dependency. Recommend (a) — install `sqlite-vec`, load it in `client.ts`, run the post-migrate. The extension is small and loading it early surfaces native-binary install issues now rather than at step 9. Flagging for confirmation.

2. **`tsconfig.base.json` `paths` resolution at build time.** Bun resolves `@arcadeai/*` via workspace symlinks at runtime, but `tsc --noEmit` needs `paths` entries to resolve types. We declare both in `tsconfig.base.json`, but if a workspace has no `references` array, project-wide type checks may not chain. Decision: declare `references` in each workspace `tsconfig.json` pointing at `../../packages/db` and `../../packages/shared` as needed. Mark as decided unless review pushes back.

3. **Root `dev` parallelism.** SPEC §4 sanctions a `concurrently` fallback if Bun's `--filter` parallel watch is flaky. Verify on first run; no decision needed up front.

## Acceptance criteria

A reviewer can confirm step 1 is done by checking each of the following:

- [ ] `bun install` at repo root succeeds with no errors and links `@arcadeai/db` + `@arcadeai/shared` into the apps' `node_modules`.
- [ ] `bun run dev` at repo root starts both Vite (`:5173`) and Fastify (`:3000`) without errors.
- [ ] `curl -s http://localhost:3000/api/health` returns `{"ok":true,"version":"<x.y.z>"}` matching `apps/server/package.json`'s `version`.
- [ ] The web app, loaded at `http://localhost:5173`, performs a `fetch('http://localhost:3000/api/health', { credentials: 'include' })` on mount and renders the response. No CORS errors in the browser console.
- [ ] `bun run lint` (`biome check .`) passes with no errors.
- [ ] `bun run format` (`biome format --write .`) is a no-op on a freshly committed tree.
- [ ] `bun run build` (typecheck + Vite build) succeeds for all workspaces.
- [ ] `packages/db` migration runner executes successfully against a fresh SQLite file: Drizzle migrations apply, then `post-migrate.ts` creates `rag_embeddings` (verifiable by `SELECT name FROM sqlite_master WHERE name='rag_embeddings'`). *(Subject to open question 1.)*
- [ ] `LICENSE` is MIT, `README.md` documents `bun install` + `bun run dev`, `.env.example` matches SPEC §15 verbatim, `.gitignore` includes every entry from SPEC §4.
- [ ] No auth code, no Better Auth dependency, no LLM SDK dependency, no domain routes other than `/api/health` exist in the tree.
